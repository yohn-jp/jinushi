# Contributing to Jinushi

Contributions are welcome through GitHub Issues and pull requests.

## Development

Start by reading `AGENTS.md` and the repository documentation. Work from the current `main` branch on an isolated branch or worktree, preserve unrelated work, and keep changes scoped to the task being addressed.

Use the repository's documented toolchain and verification commands. Do not weaken or skip repository checks merely to make a change pass.

## Pull requests

Keep pull requests focused and describe the delivered behavior, relevant constraints, and validation actually performed. A passing check is evidence for the boundary it exercises; do not claim unexecuted, skipped, or environment-blocked checks as passed.

Do not merge, force-push, rewrite shared history, or change repository settings without explicit authority.

## Documentation

Update documentation when public behavior, architecture, installation, operation, or compatibility changes. Preserve useful design rationale and avoid documenting target behavior as already implemented when it is not.

## Security

Follow [Security Policy](./SECURITY.md). Never include credentials, private keys, authorization headers, tokens, or sensitive private payloads in Issues, pull requests, logs, fixtures, or retained evidence.
